The git repo is the database — every run commits new parquet rows, so history accrues in version control and any day can be replayed. Same architecture as our memory-cycle project GlutClock.

Design decisions worth knowing

  • Baskets are compounded equal-weight returns, never averaged prices — averaging prices across listings with different histories breaks the moment a constituent starts trading (TLN).
  • Holiday gaps are forward-filled before rolling windows; US calendars have single-day holes that silently poison naive rolling stats.
  • Concentration is measured by price spread (SPY vs RSP) rather than index weights — historical shares-outstanding data isn't freely available daily; the cap-vs-equal-weight return spread is the standard price-based proxy for the same phenomenon.
  • Z-scores use rolling 250-day windows (min 100), so "stretched" always means stretched versus the recent year, not versus all history. Values clipped at ±2 so no single gauge can pin the thermometer.
  • No lookahead: supervised targets are future returns of the basket; training split is chronological (first 80% train / last 20% test), never shuffled.
  • Ledger integrity: each run stores a hash of its feature snapshot; scored outcomes join back by run_date + horizon against realized basket returns.

Honest limitations

  • The AI complex has ~one observable boom in-sample; every z-score window overlaps it. Statistical power is inherently low — treat temperature as ordinal (rising/falling, hot/cold), not cardinal.
  • Five-day equity direction is barely predictable; expect test Brier near 0.24–0.25 forever. The value is the calibration machinery, not the edge.
  • Fundamentals anchor depends on manual CSV updates between earnings seasons.
  • BTC is a noisy risk-appetite proxy (weight capped at 10%).
  • All of it: research tooling. Nothing here is investment advice.
